Asynchronous logging is off by default. To turn it on call ```spdlog::set_async_mode(q_size)```

This will make spdlog to create and use  [async_logger](https://github.com/gabime/spdlog/blob/master/include/spdlog/async_logger.h) objects instead of the regular ones.


When the user logs a message to an async logger the following happen:

1. If the queue is not full, the log message is pushed into it. Otherwise, if the queue is full (the number of messages in it reached ```max_size```), the call blocks until there is room again (or optionally spdlog discards the message and returns immediately to the caller - see below)

2. The worker thread pops the message from the queue and logs the message using the logger's sinks.

#### Full queue policy
User can decide what to do when the queue is full:
* Block the call until there is more room (default behaviour)
* Discard the message and never block - by setting the ```spdlog::async_overflow_policy```:
```c++
spdlog::set_async_mode(q_size, spdlog::async_overflow_policy::discard_log_msg)
```

#### Thread safety
async loggers are always thread safe.

#### Warm-up and teardown functions
Sometimes the user needs to do some initialization on the newly created worker thread (for example set thread affinity or priority, attach worker thread to a JVM).
Or he might wish to execute some code before thread exit (for example when detaching thread from a JVM).

To achieve this the user can provide callback functions or lambdas to the ```set_async_mode``` call:

```c++
auto warmup = []() {/* Some init code in the worker thread*/};
auto flush_interval_ms = std::chrono::milliseconds::zero();
auto teardown = []() {/* Some cleanup code in the worker thread*/};
spdlog::set_async_mode(q_size, spdlog::async_overflow_policy::block_retry, warmup, flush_interval_ms, teardown);
```

#### Windows issues
There is a bug in VS runtime that cause the application dead lock when it exits. If you use async logging, please make sure to call spdlog::drop_all() before main() exit.
If some loggers are not in the registry, those should be released manually as well.
